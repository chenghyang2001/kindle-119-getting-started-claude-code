  * **2. 檔案內容撰寫範例 (以 React + TypeScript 專案為例)**：
    ```markdown
    # CLAUDE.md

    ## Stack
    - React 18 with TypeScript 5.3
    - Vite as bundler
    - TanStack Query for data fetching
    - Zustand for global state
    - Tailwind CSS for styling

    ## Component Conventions
    - Components in PascalCase, one component per file
    - Props always typed with interfaces, never with type alias
    - Custom hooks start with `use` and go in `src/hooks/`
    - Never use `any`. If you need to escape the type system, use `unknown` and 
add a comment explaining why

    ## Folder Structure
    - `src/components/` — reusable components
    - `src/pages/` — page components (routes)
    - `src/hooks/` — custom hooks
    - `src/store/` — Zustand slices
    - `src/api/` — fetching functions (no business logic)

    ## Patterns
    - Data fetching always with TanStack Query, never with useEffect directly
    - Server state: TanStack Query. Local state: useState. Global UI state: 
Zustand
    - Page components don't fetch directly, they delegate to hooks

    ## Prohibitions
    - Don't install dependencies without asking first
    - Don't use Redux (migrated to Zustand)
    - Don't use CSS modules or styled-components (we use Tailwind)
    - Don't modify `vite.config.ts` without consulting

    ## Tests
    - Vitest + Testing Library
    - Run: `npm test`
    - Tests go in `__tests__/` next to the file they test
    ```
  * **3. 操作說明**：
    * **無斜線指令**：Claude Code 啟動時會**自動讀取並合併**各階層的

### 第 7 章：.claude 資料夾

* **(a) 具體操作步驟與指令**：
  * **1. 建立 `.claude` 工具箱目錄結構**：
    在專案根目錄（或全域家目錄 `~/.claude/`）建立以下目錄結構：
    ```text
    .claude/
    ├── CLAUDE.md
    ├── commands/
    ├── agents/
    ├── skills/
    ├── rules/
    └── settings.json
    ```
  * **2. 建立與呼叫自訂斜線指令 (Custom Commands)**：
    * **建立 PR 審查指令檔案**：`.claude/commands/review-pr.md`
      ```markdown
      <!-- .claude/commands/review-pr.md -->
      Review the current PR changes following these steps:
      1. Run `git diff main...HEAD` to see all changes
      2. Identify potential security issues
      3. Verify there are tests for the new functionality
      4. Check that the code follows the conventions in CLAUDE.md
      5. Summarize findings in a list with severity (critical/medium/low)
      If you find critical issues, show them first.
      ```
    * **呼叫斜線指令**：在對話中輸入：
      ```text
      /review-pr
      ```
    * **建立帶參數的指令檔案**：`.claude/commands/explain.md`
      ```markdown
      <!-- .claude/commands/explain.md -->
      Explain the file or function $ARGUMENTS clearly and concisely.
      Include:
      - What it does and why it exists
      - Important dependencies
      - Edge cases it handles
      ```
    * **帶參數呼叫指令**：
      ```text
      /explain src/auth/middleware.ts
      ```
    * *(全域指令：可放置於 `~/.claude/commands/`，如 
`standup.md`、`check-deps.md`、`todo.md`)*。
  * **3. 建立專長技能 (Skills)**：
    * **建立技能檔案**：`.claude/skills/security-checker/SKILL.md`
      ```markdown
      <!-- .claude/skills/security-checker/SKILL.md -->
      # Security Checker

      ## Description
      Specialist in detecting security vulnerabilities in code.

      ## When to activate
      When reviewing code or when security topics are mentioned.

      ## Instructions
      - Look for SQL injection, XSS, CSRF, and the OWASP Top 10
      - Verify that user inputs are validated and sanitized
      - Check that credentials are not hardcoded
      - Review that dependencies have no known CVEs
      - Classify each finding: critical, high, medium, low
      ```
    * **觸發方式**：無須斜線指令，當對話提及相關主題或進行 Code Review 
時，Claude 會**自動啟用**該技能。
  * **4. 建立自訂代理人 (Custom Agents)**：
    * **建立代理人檔案**：`.claude/agents/reviewer.md`
      ```markdown
      <!-- .claude/agents/reviewer.md -->
      ---
      name: Reviewer
      description: Reviews code for bugs, security, and style
      model: sonnet
      tools:
        - Read
        - Grep
        - Glob
      ---

      You are an experienced code reviewer. Your job is to find problems before 
they reach production.

      ## Rules
      - Review each file individually
      - Classify findings by severity: critical, high, medium, low
      - Don't report style issues already covered by the linter
      - Prioritize: security > correctness > performance > readability
      - If you find no problems, say so clearly. Don't make things up.
      ```
  * **5. 設定 Hooks 與細粒度 Rules**：
    * **設定工具執行前後 Hook 檔案**：`.claude/settings.json`
      ```json
      {
        "hooks": {
          "PreToolUse": [
            {
              "matcher": "Edit",
              "command": "echo 'Claude is about to edit a file'"
            }
          ],
          "PostToolUse": [
            {
              "matcher": "Bash",
              "command": "./scripts/validate-after-change.sh"
            }
          ]
        }
      }
      ```
    * **建立獨立規則檔案**：`.claude/rules/no-console-log.md`
      ```markdown
      <!-- .claude/rules/no-console-log.md -->
      Never use console.log for debugging in production code.
      Use the project's logger (src/utils/logger.ts).
      ```
  * **6. 實戰組合工作流**：
    * 建立組合命令 `.claude/commands/review.md` 後，輸入 `/review` 
可同時觸發獨立執行的 `reviewer` Agent 進行審查，並結合 `security-checker` Skill 
的專業安全知識。
* **(b) 書中提到的範例專案或 GitHub 網址**：
  * 無特定 GitHub 範例專案網址，上述組態皆建立於讀者專案本機的 `.claude/` 
資料夾內。
* **(c) 需要的外部環境、API key 或帳號**：
  * **外部環境**：Git 版本管制（用以將 `.claude/` 工具箱推至 GitHub/GitLab

  * **API key / 帳號**：已啟動的 Claude Code CLI 帳號。
